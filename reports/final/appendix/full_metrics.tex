\section{Essential Evaluation Details}
\label{app:full-metrics}

The main retrieval table is generated by:
\begin{verbatim}
python eval/retrieval/run_retrieval_eval.py --mode realistic-crossdoc \
  --output-prefix realistic-crossdoc
\end{verbatim}
The fixture uses five user-facing questions over the skill-security demo corpus. The generated Markdown and JSON artifacts store the per-question expected pages, retrieved evidence pages, recall@5, and full-support flags.

The report-facing table is stored as \artifact{realistic\_crossdoc\_metrics.md} under \artifact{reports/final/results/}. The machine-readable per-question rows are stored as \artifact{realistic-crossdoc.json} under \artifact{eval/retrieval/results/}. The same command also writes CSV and Markdown summaries beside the JSON file.

The live local smoke evidence is intentionally summarized rather than reproduced in full. The essential records are \artifact{live\_local\_test\_log.md} and \artifact{agent\_trace\_examples.md} under \artifact{reports/final/results/}. These files support the bounded-agent claims in the main text: first-pass sufficient answers, missing-evidence retry, \texttt{no\_new\_evidence} termination, citation filtering, and prompt-injection-like PDF text staying inside the evidence boundary.
